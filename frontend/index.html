So sánh NoSQL vs SQL

Phân tích học thuật cho đề tài báo cáo: Tại sao MongoDB phù hợp hơn SQL cho bài toán này?

M

MongoDB (NoSQL)

  • Schema-less: mỗi sản phẩm có thuộc tính riêng biệt
  • Không cần sửa cấu trúc khi thêm loại sản phẩm mới
  • Aggregation Pipeline mạnh mẽ, trực tiếp trên DB
  • Dễ dàng scale-out theo chiều ngang (Sharding)
  • JSON native — phù hợp với API hiện đại
  • ACID transaction ít mạnh hơn SQL
  • Không có JOIN chuẩn
SQL

MySQL / PostgreSQL (SQL)

  • ACID transaction mạnh, phù hợp ngân hàng
  • JOIN phức tạp được hỗ trợ hoàn toàn
  • Schema cố định giúp kiểm soát dữ liệu chặt chẽ
  • Schema cứng: phải ALTER TABLE khi thêm thuộc tính mới
  • EAV Pattern (entity-attribute-value) rất chậm và phức tạp
  • Cột NULL lãng phí khi sản phẩm đa dạng
  • Scale-up (nâng cấp máy chủ) tốn kém hơn
